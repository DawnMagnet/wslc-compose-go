## wslc-compose v0.1.3

Bug-fix release: `up` is idempotent again and `down -v` removes networks and volumes on localized Windows.

### Install / upgrade (Windows PowerShell or PowerShell 7, no admin required)

```powershell
irm https://raw.githubusercontent.com/DawnMagnet/wslc-compose-go/main/scripts/install.ps1 | iex
```

Pin this version:

```powershell
& ([scriptblock]::Create((irm https://github.com/DawnMagnet/wslc-compose-go/releases/download/v0.1.3/install.ps1))) -Version v0.1.3
```

Then open a new terminal:

```powershell
wslc-compose version     # main command, works in every shell
wslc compose version     # PowerShell sugar, forwards to wslc-compose
```

### Changes

- **Fixed: second `up` failed with `ERROR_ALREADY_EXISTS`, and `down -v` left networks and volumes behind**
  ([#1](https://github.com/DawnMagnet/wslc-compose-go/issues/1), [#2](https://github.com/DawnMagnet/wslc-compose-go/pull/2)).
  `wslc network list` and `wslc volume list` print tables with localized headers (for example `名称` / `卷名称`
  on Chinese Windows). The parser only recognised the English `NAME` header, saw no existing resources, and
  therefore tried to re-create the project network on every `up` and skipped removal in `down -v`.
  Networks and volumes are now listed with `--format json`, which does not depend on the system language.
  A re-run of `up` now reports `Container ...  Running` (or recreates the container when its configuration
  changed) and exits 0; `down -v` removes the project's networks and named volumes.
- **Fixed: ~10 s of pointless retries when a network or volume already exists.** `ERROR_ALREADY_EXISTS` is no
  longer retried for `network create` / `volume create`, because there it means the resource really exists.
  Container operations keep the existing retry on `ERROR_ALREADY_EXISTS` and `ERROR_SHARING_VIOLATION`
  (a just-stopped container's kernel object can linger briefly).

### Upgrade notes

- No compose-file or CLI changes. Resources left behind by earlier versions (for example `wcprobe_default`
  and `wcprobe_data` from a previous `down -v`) are picked up and reused by the next `up`, or removed by the
  next `down -v`.

### Assets

Same layout as v0.1.2: UPX-packed `windows-amd64` / `linux-amd64` binaries, uncompressed arm64 binaries,
`install.ps1`, the `wslc compose` wrappers and `checksums.txt` (SHA-256 of every asset).
