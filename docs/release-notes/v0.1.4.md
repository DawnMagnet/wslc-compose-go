## wslc-compose v0.1.4

Bug-fix release: `up --wait-timeout` accepts integer seconds like docker compose.

### Install / upgrade (Windows PowerShell or PowerShell 7, no admin required)

```powershell
irm https://raw.githubusercontent.com/DawnMagnet/wslc-compose-go/main/scripts/install.ps1 | iex
```

Pin this version:

```powershell
& ([scriptblock]::Create((irm https://github.com/DawnMagnet/wslc-compose-go/releases/download/v0.1.4/install.ps1))) -Version v0.1.4
```

Then open a new terminal:

```powershell
wslc-compose version     # main command, works in every shell
wslc compose version     # PowerShell sugar, forwards to wslc-compose
```

### Changes

- **Fixed: `up --wait-timeout 300` failed with `time: missing unit in duration "300"`**
  ([#4](https://github.com/DawnMagnet/wslc-compose-go/issues/4), [#5](https://github.com/DawnMagnet/wslc-compose-go/pull/5)).
  docker compose declares `--wait-timeout` as an integer number of seconds, so scripts written for it broke here.
  The flag now accepts a bare integer as seconds (`300`) as well as a Go duration (`20m`, `1h30m`).
  `0` still falls back to the 5m default, and negative values are now rejected instead of silently accepted.

### Upgrade notes

- Fully backward compatible: existing duration values such as `20m` keep working.

### Assets

Same layout as v0.1.3: UPX-packed `windows-amd64` / `linux-amd64` binaries, uncompressed arm64 binaries,
`install.ps1`, the `wslc compose` wrappers and `checksums.txt` (SHA-256 of every asset).
