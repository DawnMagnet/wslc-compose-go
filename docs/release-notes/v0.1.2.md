## wslc-compose v0.1.2

Installer fix release. No changes to the `wslc-compose` binary behaviour.

### Install / upgrade (Windows PowerShell or PowerShell 7, no admin required)

```powershell
irm https://raw.githubusercontent.com/DawnMagnet/wslc-compose-go/main/scripts/install.ps1 | iex
```

Pin this version:

```powershell
& ([scriptblock]::Create((irm https://github.com/DawnMagnet/wslc-compose-go/releases/download/v0.1.2/install.ps1))) -Version v0.1.2
```

Then open a new terminal:

```powershell
wslc-compose version     # main command, works in every shell
wslc compose version     # PowerShell sugar, forwards to wslc-compose
```

### Changes

- **Fixed: `wslc compose` missing in PowerShell 7.** Windows PowerShell 5.1 and PowerShell 7 read separate
  profiles (`Documents\WindowsPowerShell\profile.ps1` vs `Documents\PowerShell\profile.ps1`). `install.ps1`
  previously wired only the profile of the shell it ran in. It now adds the `wslc compose` wrapper line to
  both profiles, whichever shell you install from, and `-Uninstall` removes it from both.
  Re-run the installer to upgrade; the operation is idempotent.

### Assets

Same layout as v0.1.1: UPX-packed `windows-amd64` / `linux-amd64` binaries, uncompressed arm64 binaries,
`install.ps1`, the `wslc compose` wrappers and `checksums.txt` (SHA-256 of every asset).
