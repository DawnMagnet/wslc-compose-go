## wslc-compose v0.1.5

Bug-fix release: host port ranges published to a single container port (`"8000-8002:80"`) now work.

### Install / upgrade (Windows PowerShell or PowerShell 7, no admin required)

```powershell
irm https://raw.githubusercontent.com/DawnMagnet/wslc-compose-go/main/scripts/install.ps1 | iex
```

Pin this version:

```powershell
& ([scriptblock]::Create((irm https://github.com/DawnMagnet/wslc-compose-go/releases/download/v0.1.5/install.ps1))) -Version v0.1.5
```

Then open a new terminal:

```powershell
wslc-compose version     # main command, works in every shell
wslc compose version     # PowerShell sugar, forwards to wslc-compose
```

### Changes

- **Fixed: `ports: "8000-8002:80"` made `up` fail with `E_INVALIDARG`**
  ([#7](https://github.com/DawnMagnet/wslc-compose-go/issues/7), [#8](https://github.com/DawnMagnet/wslc-compose-go/pull/8)).
  The range was passed to wslc unchanged as `-p 8000-8002:80`, but wslc requires both sides of a range to have the same length.
  Following Compose semantics, wslc-compose now binds the first free host port in the range (TCP/UDP aware, respecting `host_ip`),
  and falls back to the first port if none is free so wslc reports the conflict. Equal-length ranges such as `9000-9001:9000-9001`
  are unchanged, and the chosen port does not cause containers to be recreated on the next `up`.

### Upgrade notes

- Fully backward compatible.
