## wslc-compose v0.2.0

Compose coverage release: multiple networks, secrets and configs, `extra_hosts` / `host-gateway`, and `build --secret`. Unsupported compose-spec fields warn, and `--strict` turns those warnings into errors.

### Install / upgrade (Windows PowerShell or PowerShell 7, no admin required)

```powershell
irm https://raw.githubusercontent.com/DawnMagnet/wslc-compose-go/main/scripts/install.ps1 | iex
```

Pin this version:

```powershell
& ([scriptblock]::Create((irm https://github.com/DawnMagnet/wslc-compose-go/releases/download/v0.2.0/install.ps1))) -Version v0.2.0
```

Then open a new terminal:

```powershell
wslc-compose version     # main command, works in every shell
wslc compose version     # PowerShell sugar, forwards to wslc-compose
```

### Changes

- **Multiple networks per service** ([#10](https://github.com/DawnMagnet/wslc-compose-go/pull/10)).
  Every declared network is created (project-prefixed name; `external` networks are only checked).
  The container is created on the highest-priority endpoint (`--network`, `--ip`, `--network-alias`) and the others
  are attached with `wslc network connect` before `start`. A single network still uses `wslc run -d`.
  On wslc 3.0.3.0+, IPAM `ip_range` is passed as `network create --ip-range`. Before any wslc call,
  an `ip_range` outside its subnet, an `ip_range` with no usable IPv4 subnet, an invalid `ip_range` CIDR,
  and static IP subnet problems are hard errors. An IPv6-only subnet without `ip_range` warns and is
  passed through. Replicas cannot share one static address.
- **Secrets and configs.** `file:` sources are mounted read-only at `/run/secrets/<name>` or the config target.
  `environment:` and `content:` are written under the project state directory and removed by `down`.
  Generated files are replaced atomically, so a second `up` can rewrite a read-only file. `build.secrets` becomes
  `wslc build --secret` when the binary accepts it.
- **`extra_hosts` and `host-gateway`.** Entries are written to `/etc/hosts` after start. `host-gateway` is the
  container's default route. Published-port hairpin uses session iptables (`wslc system session run`) on
  wslc 3.0.3.0 or newer and is removed by `down`.
- **wslc version detection and a compose-spec sweep.** `wslc --version` decides which flags are sent.
  Multi-network attach, static IPv4, `--ip-range`, `build --secret` and host-gateway DNAT are skipped with a
  warning on older binaries. Fields wslc cannot express (restart, capabilities, devices, sysctls, logging, and
  the rest of the README matrix) warn instead of being dropped silently. `--strict` turns those warnings into
  errors. `--dry-run` with no wslc binary plans the current feature set.

### Upgrade notes

- On wslc 3.0.1, compose files that do not use secrets, configs or `extra_hosts` produce the same `run` and
  `network create` lines as v0.1.5 (golden-tested): static addresses and `ip_range` stay warnings, `up` still
  succeeds, and `--ip-range` is not sent. Secrets, configs and `extra_hosts` are now applied on every wslc
  version (v0.1.5 ignored them), so services using them get new mounts / an `/etc/hosts` update and are
  recreated once after upgrading.
- Config hashes are unchanged for services that do not use a new feature, so upgrading does not recreate those
  containers. `minimal.yaml` hello stays `0df62ea0…`. Schema version 2 is mixed in for mounted secrets, configs
  and `extra_hosts`. Those services are recreated once on the first `up` after upgrading, on any wslc version.
  The `3.0.3` tier is added only for multiple networks, static IPv4 and secondary endpoint
  options. `ip_range`, `build.secrets`, external secrets and external configs do not change the hash.
  Moving from wslc 3.0.1 to 3.0.3 recreates only services whose container command changes.
- New behaviour is gated on wslc 3.0.3.0: multi-network attach, static IPv4, `--ip-range`, `build --secret`
  and host-gateway session DNAT. Older builds keep the single-network path and warn.
- `--strict` rejects an unknown `wslc --version` on `up`, `run` and `build` before any wslc mutation, and still
  allows `down`, `start`, `stop`, `restart`, `ps`, `logs` and `exec`. Unsupported or version-gated fields still
  fail every command under `--strict`, as in v0.1.5. An unreadable version does not recreate
  containers. A service is warned only when its stored hash matches neither the legacy nor the 3.0.3 digest
  of the current config.

### Not verified

- Real wslc 3.0.3 IPv6 subnet behaviour. An IPv6 subnet with no `ip_range` is a warning and the subnet is still
  passed to `network create`; an `ip_range` with no usable IPv4 subnet is a hard error on 3.0.3 before any
  command. That path is covered by the mocked Runner only.
- Windows file-in-use and junction handling. Replacing a generated secret or config that a running container
  still has mapped (`ERROR_SHARING_VIOLATION`), and whether a junction is treated like the symlink the state
  directory refuses to follow, needs a real Windows machine.
- Every wslc 3.0.3.0-only path (multi-network create/connect, `--ip`, `--ip-range`, `build --secret`,
  session iptables DNAT) is covered by the mocked Runner only; real-machine verification so far is on wslc 3.0.1.
- Ownership and permissions of mounted secret files inside the WSL VM.
- `extra_hosts` is written with `wslc exec` after the container starts, so an entrypoint that reads `/etc/hosts`
  immediately may not see the entries.

### Assets

Same layout as v0.1.5: UPX-packed `windows-amd64` / `linux-amd64` binaries, uncompressed arm64 binaries,
`install.ps1`, the `wslc compose` wrappers and `checksums.txt` (SHA-256 of every asset).
